# Systems Mastery 0.4.8 — Graph Traversal

> Trees rely on structure to guarantee traversal. Graphs require algorithms to guarantee correctness.

---

# Objective

The previous module introduced graphs as the general abstraction for representing arbitrary relationships.

Unlike trees, graphs no longer guarantee hierarchy.

Nodes may be reachable through multiple paths.

Cycles may exist.

Entire groups of nodes may even remain disconnected from one another.

Representation alone is therefore no longer sufficient.

This module asks a different engineering question:

> How can arbitrary relationships be explored safely and completely?

The purpose is not to memorize traversal algorithms.

The purpose is to understand why graphs require additional algorithmic state, why tree traversal cannot simply be reused, and how traversal strategies emerge from the absence of structural guarantees.

---

# When Structure Stops Helping

Tree traversal is remarkably simple because the structure itself guarantees correctness.

Every node has exactly one parent.

Every node is reachable through exactly one path.

Cycles cannot exist.

A recursive traversal therefore never needs to remember where it has already been.

Graphs remove all of these guarantees.

A node may be reached through multiple paths.

Cycles may return to previously explored nodes.

Traversal correctness can no longer be delegated to the structure.

The algorithm must now preserve correctness explicitly.

---

# Multiple Paths

Unlike trees, graphs do not guarantee a unique path to every node.

```text
A
├── B
│   └── D
└── C
     \
      D
```

The same node may be discovered through multiple routes.

Without additional state, traversal would process the same node repeatedly.

Traversal therefore requires remembering which nodes have already been discovered.

---

# Cycles

Graphs may also contain cycles.

```text
A → B → C
↑       ↓
└───────┘
```

A traversal that blindly follows outgoing edges would never terminate.

The problem is not recursion itself.

The problem is revisiting previously explored nodes.

Correct graph traversal therefore requires distinguishing between:

* nodes never seen before;
* nodes already discovered.

---

# Traversal State

Graphs do not store traversal information.

The graph represents relationships.

The traversal algorithm represents exploration.

For this reason, visited nodes belong to the algorithm rather than the graph itself.

Traversal state is temporary.

Each execution maintains its own exploration history.

Once traversal completes, that state disappears.

---

# Discovery Before Exploration

A node must be marked as visited immediately after being discovered.

Only then should its neighbors be explored.

This guarantees that if another path reaches the same node before exploration finishes, the algorithm immediately recognizes that the node has already been discovered.

The traversal therefore preserves two essential invariants:

* every reachable node is processed exactly once;
* cycles cannot produce infinite traversal.

---

# Traversal Frontiers

Every graph traversal follows the same conceptual process.

A frontier contains nodes waiting to be explored.

The algorithm repeatedly:

* removes one node from the frontier;
* processes it;
* discovers previously unseen neighbors;
* adds those neighbors to the frontier.

Different traversal algorithms differ only in how the frontier is managed.

The exploration model itself remains identical.

---

# Depth-First Search

Depth-first search always continues exploring the current branch before considering alternatives.

The frontier behaves as a stack.

This stack may be:

* provided implicitly by recursive function calls;
* managed explicitly by the algorithm itself.

Both implementations perform the same traversal.

Only the storage location of traversal state changes.

---

# Breadth-First Search

Breadth-first search explores the graph one level at a time.

The frontier behaves as a queue.

Nodes discovered first are explored first.

Rather than following one branch deeply, BFS gradually expands outward from the starting node.

The traversal strategy changes.

The underlying exploration model does not.

---

# Recursive and Iterative Traversal

Recursive DFS and iterative DFS are not different algorithms.

Both perform depth-first exploration.

The only difference is where suspended work is stored.

Recursive traversal delegates this responsibility to the language call stack.

Iterative traversal stores the same information explicitly inside a stack.

The traversal order remains conceptually identical.

---

# Connected Components

A traversal beginning from one node only reaches nodes that are connected to it.

```text
A ─ B ─ C

D ─ E
```

Starting from `A` cannot reach `D`.

Traversing an entire graph therefore requires more than one traversal.

The algorithm iterates over every node belonging to the graph.

Whenever it encounters a node that has not yet been visited, it begins a new traversal from that node.

Each traversal explores exactly one connected component.

Together they explore the entire graph.

---

# Graph Traversal in Real Systems

Graph traversal appears throughout software engineering.

* Search engines crawl hyperlinks.
* Version control systems explore commit histories.
* Routing algorithms explore communication networks.
* Dependency managers analyze package relationships.
* Social platforms discover connected users.

Although these systems solve different problems, they all rely upon the same fundamental idea:

Safely exploring arbitrary relationships while avoiding repeated work.

---

# Looking Beyond Traversal

Graph traversal solves one important problem:

Visiting connected nodes correctly.

It does not yet answer questions such as:

* Which path is shortest?
* Which nodes are most important?
* Can a cycle be detected?
* Is one node reachable from another?

These questions require additional algorithms built upon the traversal principles introduced in this module.

---

# Core Mental Model

When reasoning about graph traversal, ask:

```text
Can this graph contain cycles?
Can multiple paths reach the same node?
Which information belongs to the graph?
Which information belongs only to the traversal?
What defines the traversal frontier?
Does the frontier behave like a stack or a queue?
Can one traversal reach every node in the graph?
```

These questions matter more than memorizing DFS or BFS.

They transform graph traversal from a collection of algorithms into a systematic method for safely exploring arbitrary relationships.
